Questions

What is document-driven UI?

A JSON document describes the structure and behavior of a screen. The client validates that document against a vocabulary and renders it with native components, so a screen can change without shipping new layout code.

Is this server-driven UI?

You can use it that way, but Milano itself is client-only and needs no backend. Documents can come from your API, a CDN, a feature-flag payload, or the app bundle. Serve them remotely and you get server-driven UI without a server-side rendering stack.

Does Milano replace my design system?

No. Milano draws nothing. It resolves a document into calls to the SwiftUI, Compose, and React components you already own, so your typography, spacing, and theming stay yours.

Which platforms are supported?

SwiftUI on iOS, iPadOS, macOS, and watchOS (MilanoSDK); Compose on Android and the JVM (dev.get-milano:engine-compose); React on the web and React Native (@get-milano/react). Each link is that engine's API reference.

How does rendering stay identical across platforms?

Every engine implements the same normative specification and passes the same conformance suite. Invalid documents are rejected at the gate before anything renders, so a document either works everywhere or fails everywhere.

What is it good for?

Surfaces that change faster than your release train: remotely configurable banners, interstitials, onboarding, promos, and forms, updated without waiting on an app store review.
